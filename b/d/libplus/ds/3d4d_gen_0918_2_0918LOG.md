## 1. 前置检查

### 1.1 发现的问题

**问题 E1: Lift MJCF 文件缺失**

- **现象**: `evaluation/panda_robosuite_lift.xml` 不存在于仓库中
- **根因**: 该文件需要通过 robosuite 导出，未被 git-tracked
- **修复**: 在 LIBERO venv 中通过 EGL monkey-patch 导出（见 Step 0）

**问题 E2: VLA venv 无 mujoco**

- **现象**: `/B/VENV/itnvla15rbt20/` 中没有安装 mujoco
- **根因**: 该 venv 是训练用 venv，原始安装未包含 mujoco
- **修复**: `pip install mujoco` → 安装了 mujoco 3.13.0
- **影响**: 无副作用，mujoco 是纯 Python/C 包

**问题 E3: robosuite 无法在 LIBERO venv 导入**

- **现象**: `import robosuite` 失败，报 `ImportError: Cannot initialize a EGL device display`
- **根因**: robosuite 在 `__init__.py` 导入链中 (`__init__` → `environments/base.py` → `binding_utils.py` → `egl_context.py`) 强制 `from mujoco.egl import egl_ext as EGL`，而当前环境无 EGL 设备
- **修复**: 通过 Python monkey-patch 注入假的 `mujoco.egl.egl_ext` 模块，提供所有 robosuite 引用的 EGL 常量和函数作为 no-op。代码：
  ```python
  fake_egl_ext = types.ModuleType('mujoco.egl.egl_ext')
  for name in ['EGLConfig','EGL_ALPHA_SIZE','EGL_BLUE_SIZE','EGL_COLOR_BUFFER_TYPE', ...]:
      setattr(fake_egl_ext, name, 0)
  for attr in ['eglBindAPI','eglChooseConfig', ...]:
      setattr(fake_egl_ext, attr, lambda *a, **k: 0)
  sys.modules['mujoco.egl'] = fake_egl
  sys.modules['mujoco.egl.egl_ext'] = fake_egl_ext
  ```
- **影响**: 仅影响导出 MJCF 的一次性操作，不影响后续 FK 计算

**问题 E4: 方案假设了 LeRobot v3 源数据，但实际只有 RLDS**

- **现象**: 方案中的 `generate_libero_kpt_v2.py` 期望 LeRobot v3 parquet 格式输入，但 `/B/Dta/opvla_libero/` 是 RLDS TFRecord 格式
- **根因**: 方案编写时假设已有 `port_libero.py` 完成了 RLDS → LeRobot 转换，但实际未执行过
- **修复**: 新写 `b/s/libplus/rlds_to_lerobot_4d.py` — 直接读取 RLDS TFRecord（使用 `b/d/libplus/ds/asset/rlds_reader.py` TF-free 读取器），同时完成 FK 计算和 LeRobot v3 格式输出
- **影响**: 输出包含完整的 LeRobot v3 数据集（parquet + video），可直接用于训练

**问题 E5: ffmpeg 不可用**

- **现象**: `which ffmpeg` 返回空，系统和 venv 中均无 ffmpeg
- **根因**: 容器/环境未安装 ffmpeg
- **修复**: 使用 `cv2.VideoWriter` 的 `mp4v` 编码器代替 ffmpeg 编码视频
- **影响**: 输出的 MP4 使用 mp4v 编码而非 h264，文件可能略大，但功能等价

**问题 E6: rlds_reader.py 模块路径解析错误**

- **现象**: `rlds_to_lerobot_4d.py` 中 `Path(__file__).resolve().parent.parent.parent` 解析为 `/B/SRC/itvlaGpLibPlus/b` 而非项目根 `/B/SRC/itvlaGpLibPlus`
- **根因**: `b/s/libplus/rlds_to_lerobot_4d.py` 到项目根需要 `.parents[3]`（上4层: `libplus → s → b → project_root`），初版代码用了 `.parent.parent.parent`（3层）
- **修复**: 改为 `Path(__file__).resolve().parents[3]`
- **影响**: 无

## 6. 输出数据集结构

```
~/b/Dta/opvla_libero_4d/
├── data/chunk-000/
│   ├── episode_000000.parquet
│   ├── episode_000001.parquet
│   └── ... (共 1,693 个 parquet)
├── meta/
│   ├── info.json           # LeRobot v3 元数据
│   ├── episodes.jsonl      # 每 episode 的 task 和 length

│   └── keypoints_meta.json # R_pad, bodies, 坐标系等
└── videos/chunk-000/
    ├── observation.images.image/    # agentview MP4 videos
    │   ├── episode_000000.mp4
    │   └── ...

        └── ...
```

每个 parquet 包含的列：

| 列名 | dtype | shape | 说明 |
|------|-------|-------|------|
| `observation.state` | float32 | [8] | EEF pos(3) + axisangle(3) + gripper(2) |
| `observation.state.joint_position` | float32 | [7] | 7 个臂关节角度 |
| `action` | float32 | [7] | OSC_POSE 增量 + gripper |
| `observation.keypoint_3d` | float32 | [56] | 8 × 7D 关键点 (pos/R_pad + quat xyzw) |
| `timestamp` | float32 | [1] | 帧时间戳 (frame_idx / fps) |
| `frame_index` | int64 | [1] | episode 内帧索引 |
| `episode_index` | int64 | [1] | 全局 episode 索引 |
| `index` | int64 | [1] | 全局帧索引 |
| `task_index` | int64 | [1] | 任务索引 |
